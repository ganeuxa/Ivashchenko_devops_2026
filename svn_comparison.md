# Git vs SVN

## 1. Почему в Git ветвление «дешёвое», а в SVN «дорогое»?

В Git ветка это файл в `.git/refs/heads`, внутри которого записан хеш одного коммита. Создать ветку значит записать 41 байт, поэтому это происходит мгновенно на проекте любого размера. Переключение тоже локальное, сеть не нужна.

В SVN ветку делают командой `svn copy trunk branches/feature`. На сервере это дешёвая копия, но у разработчика появляется отдельная папка, которую надо выкачать по сети. Слияние в SVN долго было ручным: до версии 1.5 он не запоминал, какие ревизии уже слиты, и их приходилось отслеживать самому. Поэтому в SVN ветки заводят редко, а в Git на каждую задачу.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет. История и сам репозиторий лежат только на центральном сервере, а у разработчика есть рабочая копия последней ревизии. Коммит в SVN сразу отправляется на сервер, и без связи с ним его некуда записать. Офлайн можно только править файлы и смотреть `svn diff` относительно того, что скачано.

В Git у каждого полная копия репозитория со всей историей. Коммиты, ветки и `git log` работают без сети, а на сервер всё уходит потом через `git push`.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

Когда в репозитории много больших бинарных файлов: игровые текстуры и модели, CAD-чертежи, макеты. Git при клонировании скачивает все версии всех файлов, а в SVN можно выкачать одну нужную папку в последней ревизии.

Когда файлы нельзя слить. Два человека не смогут объединить правки в одном `.psd`, и в SVN такой файл можно заблокировать через `svn lock`, пока с ним работаешь.

Когда нужны права на отдельные папки. В SVN доступ настраивается на уровне директорий, в Git только на весь репозиторий. Этим пользуются в банках и госсекторе.

И в старых проектах, которые давно живут в SVN. Там переезд на Git стоит дороже, чем даёт.
