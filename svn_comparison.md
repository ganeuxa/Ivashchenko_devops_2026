# Git vs SVN

## 1. Почему в Git ветвление «дешёвое», а в SVN — «дорогое»?

В Git ветка — это просто файл с указателем (40-символьный хеш) на коммит. Создать ветку = записать один маленький файл, это происходит мгновенно и не зависит от размера проекта. Переключение между ветками тоже локальное.

В SVN ветка — это копия директории на сервере (`svn copy trunk branches/feature`). Хотя сервер хранит её как «лёгкую копию», для разработчика это отдельная папка, которую надо выкачивать по сети, а слияние веток исторически было ручным и болезненным (SVN долго не отслеживал, что уже было смержено). Поэтому в SVN ветки заводят редко, а в Git — на каждую задачу.

## 2. Можно ли в SVN сделать коммит без интернета? Почему?

Нет. SVN — централизованная система: история и репозиторий живут только на центральном сервере, а у разработчика лежит лишь рабочая копия последней версии. Коммит — это отправка изменений на сервер, без связи с ним коммитить некуда. Офлайн можно только редактировать файлы и смотреть локальный diff.

В Git у каждого полная копия репозитория, поэтому коммиты, ветки, просмотр истории работают без сети, а на сервер изменения уходят потом через `git push`.

## 3. В каких сценариях SVN до сих пор может быть предпочтительнее Git?

- **Большие бинарные файлы** (игровые ассеты, CAD-модели, дизайн-макеты): SVN не заставляет каждого скачивать всю историю всех версий, можно выкачать только нужную папку.
- **Блокировки файлов (lock)**: для бинарников, которые невозможно смержить, SVN позволяет «захватить» файл, чтобы никто другой его не правил.
- **Строгий централизованный контроль доступа**: права можно выдавать на отдельные директории, удобно для банков и госсектора.
- **Легаси-проекты**, которые исторически живут в SVN, и перенос которых дороже, чем выгода от Git.
- **Очень большие монорепозитории**, где нужно выкачивать только часть дерева (partial checkout).
